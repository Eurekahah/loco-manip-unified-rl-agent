# （模板）缺陷 / 特性记录条目

> 用途：`docs/review/DEFECT_LOG_zh.md` 里**每条**记录都按这个骨架写，
> 一条记录 = 一个"可回溯的事件"，方便日后查"当时为什么这么改"。
>
> 复制下面 `### DEF-0xx ...` 整段追加到 DEFECT_LOG 的"记录"区（新条目放最上面）。

---

### DEF-0xx `<一句话标题：现象 + 影响面>`

| 项 | 内容 |
|---|---|
| 日期 | `YYYY-MM-DD` |
| 类型 | `缺陷` / `特性` / `重构` / `文档` |
| 状态 | `已修` / `部分已修` / `未修（见 TODO_zh.md P?）` |
| 关联 | `<分支> @ <commit>`；`<文件:符号名>`；相关条目 `DEF-0yy` |

**1. 现象（怎么发现的）**

* 触发条件 / 复现命令：
* 可观测证据（报错原文、指标数字、曲线）：
* 影响面（哪些任务/哪些 checkpoint 受影响）：

**2. 根因**

* 定位过程（做过哪些排除实验）：
* 真正的原因（文件:符号名 + 一句话机制）：
* 为什么以前没暴露 / 什么时候开始暴露：

**3. 修正**

* 改了什么（文件:符号名 + 一句话）：
* 为什么这么改（备选方案是什么、为什么否掉）：
* 兼容性代价（要不要重训 / 旧 checkpoint 还能不能用）：

**4. 结果（验收）**

* 实测数据（**数字 + 复现命令**；对照组要写清差异）：
* 回归检查（跑了哪些任务、是否 exit 0）：
* 遗留问题 / 未覆盖的场景：

---

## 写这条记录时的检查清单（写完删掉）

1. 现象里有没有**原始报错/原始数字**？（不要只写"报错了"）
2. 根因是不是"可证伪"的？（有没有对照实验或独立复算支持）
3. 结果里有没有**改动前后的对比数字**？
4. 有没有写"这条修正的反面代价"（重训 / 分布变化 / 依赖别的分支）？
5. 关联里有没有 commit hash（方便 `git show`）？
